## 本轮修复与边界

- Worker 的监控监听器增加 GET/HEAD `/healthz` 与 `/readyz`。前者只表示监控 HTTP 存活，
  后者要求启动完成、Consumer 已启用且最近一次 Receive 成功；停止开始立即撤销就绪。
  探针不等待生命周期排空锁，工作池满时不因正常背压误报故障。
- RocketMQ SDK 的 `MESSAGE_NOT_FOUND`（含包装错误）被准确归类为空队列，而不是接收失败。
  传输、鉴权和 Topic 错误仍保留；非法空消息视图不再导致 panic。
- 监控路径在创建监听器前校验，拒绝保留探针路径、ServeMux 通配符及非法 URI；探针禁缓存、
  禁类型嗅探，不返回令牌、私有依赖地址或内部错误详情。
- `make worker-build` 构建独立二进制，失败构建不覆盖旧二进制；`make worker-run` / `run-judge`
  构建后以前台 `exec` 方式运行，SIGTERM / Ctrl-C 沿用现有有界退出流程。
  不自动启动基础设施、不改写环境文件、不维护 PID 文件、不强杀其他进程。
- `make worker-status` 检查 `/readyz` 的精确 HTTP 200，而不是 TCP 端口可连通；503、重定向、
  非预期状态、连接失败和响应超时均失败。检查仅面向 loopback，禁代理、不输出响应体。
  `JUDGE_METRICS_ENABLED` / `JUDGE_METRICS_LISTEN_ON` 支持覆盖 YAML，并测试保留默认值与拒绝非法输入。

**不能扩大解释的边界：**消费就绪不主动验证 Submit / Problem 业务授权、对象存储读取或真实镜像执行，
也不验证监控端口属于指定 PID。`make up/down/stop` 仍只管理原有六个 HTTP/RPC 服务，不包含 Worker。
前台运行不是生产进程守护方案；先停止 Worker，再关闭依赖。脚本只应加载可信 shell 环境文件。
